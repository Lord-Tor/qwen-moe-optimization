# Доменная специализация MoE через смещение роутера

Семестровый проект, факультет КТ, ИТМО.

Эксперимент: можно ли повысить точность MoE-модели на конкретном домене, **не дообучая её** — только смещая логиты роутера на инференсе, чтобы модель чаще выбирала «доменных» экспертов.

## Идея

В Mixture-of-Experts роутер на каждый токен выбирает top-k экспертов из десятков доступных. Гипотеза: эксперты неявно специализированы, и если подтолкнуть выбор в сторону «математических» экспертов, точность на математике вырастет — без изменения весов.

Метод в три шага:

1. **Калибровка.** На 40–100 примерах домена считаем градиент лосса по логитам роутера. Эксперты, чьё усиление сильнее всего снижает ошибку, — целевые.
2. **Смещение.** Forward-hook на инференсе добавляет bias к логитам этих экспертов и **пересчитывает top-k**.
3. **Оценка.** Accuracy на MMLU, сравнение с baseline парным тестом McNemar + бутстрап CI.

Два контроля: `self-check` (смещение реально меняет ответ) и `random-control` (случайное смещение той же силы — чтобы отделить эффект от шума перемаршрутизации).

## Результаты

### Qwen1.5-MoE-A2.7B

| Домен | Baseline | С bias | Δ, п.п. | McNemar p | 95% CI | Значимо |
|---|---|---|---|---|---|---|
| abstract_algebra | 31.0% | 42.0% | +11.0 | 0.013 | [3, 19] | да |
| college_mathematics | 31.0% | 40.0% | +9.0 | 0.049 | [1, 17] | да |
| high_school_mathematics | 28.9% | 38.5% | +9.6 | 0.014 | [2.2, 16.7] | да |
| formal_logic | 35.7% | 42.9% | +7.1 | 0.211 | [-2.4, 16.7] | нет |

Random-control незначим на всех доменах (p ≥ 0.13) — эффект даёт именно выбор доменных экспертов, а не сам факт перемаршрутизации.

С поправкой Холма–Бонферрони значимость удерживают 2 домена из 4 (abstract_algebra и high_school_mathematics).

**Оптимум силы смещения.** Зависимость имеет форму перевёрнутой U: ×1–5 помогает, ×10 и выше разрушает маршрутизацию.

**Цена специализации.** Math-конфиг, применённый к чужим доменам (право, биология, история), в рабочей зоне ×1–2 стоит ≤1.4 п.п. Обвал начинается с ×10 — там, где ломается и сама математика.

**Механизм.** На high_school_mathematics Jaccard overlap выбранных экспертов 64.6% (сменилось ~35%), confidence shift +1.96 — то есть маршрут действительно перестроился.

### OLMoE-1B-7B-0924

Метод не переносится: McNemar p > 0.05 на всех четырёх доменах, прирост в пределах шума (например, high_school_mathematics: 36 исправленных ответов против 34 сломанных).

| Домен | Δ, п.п. | McNemar p |
|---|---|---|
| abstract_algebra | +2.0 | 0.864 |
| college_mathematics | +1.0 | 1.0 |
| formal_logic | +8.7 | 0.117 |
| high_school_mathematics | +0.7 | 0.905 |

Вероятная причина — архитектура: 64 эксперта / top-8 (тоньше гранулярность, эксперты менее специализированы) и отсутствие shared expert. То есть эффект архитектурно-зависим.

## Что было неочевидно

**Пересчёт top-k.** В transformers 5.x роутер возвращает кортеж, и маршрут задаётся индексами выбранных экспертов, а не самими логитами. Пока хук смещал только логиты, не пересчитывая выбор, эффект был строго нулевым — это был главный баг.

**Токенизация.** Хвостовой пробел в промпте ломал скоринг вариантов ответа.

**OOM на OLMoE.** Решилось через `experts_implementation="eager"` вместо batched_mm.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Использовались Qwen1.5-MoE-A2.7B и OLMoE-1B-7B-0924, датасет — MMLU.

## Запуск

Калибровка (построение bias-вектора по градиентам):

```bash
python scripts/build_gradient_bias.py \
  --subject high_school_mathematics \
  --output configs/math_bias.json
```

Инференс со смещением:

```bash
python scripts/qwen_mmlu_biased.py \
  --subject high_school_mathematics \
  --bias_file configs/math_bias.json \
  --bias_multiplier 2.0
```

Массовый прогон и анализ:

```bash
sbatch scripts/run_night.sh
python scripts/analyze_all.py
```

## Ограничения и что дальше

- Оптимальный множитель выбирался по скану на тех же доменах — честнее подбирать его на отложенной валидации.
- Калибровка на 40–100 примерах: выбор экспертов шумный, устойчивость к размеру набора не проверялась.
- Метод подтверждён только на Qwen-подобной архитектуре.

Дальше интереснее всего разобраться, от чего зависит переносимость между MoE-архитектурами: какую роль играют гранулярность экспертов и наличие shared expert, и можно ли адаптировать смещение под модели вроде OLMoE.
